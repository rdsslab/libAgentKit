## Purpose
- Evaluate harness capabilities and synergy with different AI models using reproducible `demo/` tests (01–07).
- Keep harness improvements **generic and adaptable** (no task-specific/hardcoded tools such as `get_primary_ip`); favor reusable mechanisms over per-case fixes.
- Capture all available metrics per task/run: **task and per-step duration**, **token usage** (`prompt/completion/total`, `tokens_per_second`, `timing_ms`, `rounds`), **context** (`used_tokens`, `limit_tokens`, `used_percent`, `estimated`), and **tool/web diagnostics** (`toolExecutions`, `usedWeb`, `webQuery/results/source/errors`, truncation/dedup where available), plus **coherence/validation** and artifacts.
- Record **machine/environment characteristics** and compare models: `qwen3:4b-instruct-8k` (baseline), `qwen3:0.6b-16k`, and `lfm3-omni:2b`.
- Compare post-improvement rerun results against pre-improvement runs and identify generic optimization opportunities.

## Harness improvements applied (generic, pre-rerun)
Applied in `src/terminal.js`, `src/ia.js`, `src/agent.js` (and `dev/test/terminal_test.js` updated); **`npm test` passing (4/4 suites)**. No case-specific task logic was added.

- **`src/terminal.js` (`run_command`)**: safe normalization/tokenization of common malformed calls where a full command line is passed in `command` (e.g. `"ip route get 1.1.1.1"`) into `{command,args}` **without shell execution** (`shell:false`, argv). Preserves allowlist resolution, `cwd/roots` restrictions, approval/validation hooks, secret scrubbing, timeout/output caps, and audit logging; emits normalization info for diagnostics.
- **`src/ia.js` (tool loop/adapters)**: recoverable handling for unknown tool requests (structured error with available-tools guidance instead of aborting the run) and generic binary-name → `run_command` aliasing when `run_command` is available; truncation of large tool results to reduce context pressure; on `max_tool_rounds_exceeded`, adapters return partial results with diagnostics/available metrics (including usage where available) instead of hard-failing without evidence in supported paths.
- **`src/agent.js`**: truncation/budgeting of injected document and pre-search web recap context (`maxInjectedContextChars`) and propagation of execution/diagnostic flags (e.g. `incomplete`, `reason`) for better observability.

## Generic findings and optimization opportunities
- **Generic tool-call normalization/recovery helps small models:** normalizing common `run_command` shapes and converting unknown/binary tool mistakes into recoverable feedback reduced hard failures and improved some outcomes (e.g. qwen3:0.6b 02, lfm3 02/05/06) without adding task-specific tools.
- **Preserve partial diagnostics on limits:** returning partial state/usage on round limits (and structured tool errors) improves debuggability and metric completeness; extend consistently across all adapters/paths and include reason codes.
- **Context/result budgeting remains important:** truncating tool outputs and injected recaps reduces overflow risk, but models can still fail to synthesize (e.g. qwen3:0.6b 03 repeated successful curl calls with empty/incoherent answer). Consider generic policies: dedupe identical tool calls/results, summarize large command outputs (status/headers/key lines) when budgets are tight, and prompt/loop nudges to answer after sufficient evidence.
- **Web/search non-determinism dominates some outcomes:** 01 regressions correlated with different retrieved sources/snippets (Bing) and misleading content; generic mitigations include source-quality/recency heuristics, answer-vs-evidence consistency checks, and retry/refinement with alternate queries/providers when top evidence conflicts with known entities.
- **Long-form generation timeouts:** 07 step 2 for qwen3:4b-instruct-8k (and 04/06 variability for smaller models) indicates need for generic strategies: chunked generation, lower output targets with iterative refinement, streaming/checkpointed saves, or per-task token/time budgets with graceful partial artifacts.
- **Validation semantics:** distinguish transport/runtime success, artifact presence/structure, and factual coherence; keep ground-truth checks explicit (heuristics can over/under-report, as seen in prior 05 notes).
- **Operational:** sequential runs, cache/idempotent reuse where safe, and capturing connection/runtime errors with full diagnostics improve reproducibility on constrained CPU/RAM environments.
